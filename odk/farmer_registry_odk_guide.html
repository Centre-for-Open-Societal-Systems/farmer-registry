1. Executive Summary

This document delivers the comprehensive end-to-end technical reference and operational runbook for the automated ingestion of Ethiopian smallholder farmer profiling data from ODK Central into the OpenG2P Gen 2 Farmer Registry.

The architecture replaces Gen 1 batch manual spreadsheet imports with an automated, event-driven, decoupled integration. Offline mobile data collection by field enumerators across rural Ethiopia is automatically collected, normalized, transformed, and staged in OpenG2P with full deduplication, relational unnesting of repeat groups (land parcels, crops, livestock), and multi-lingual support.

Core Principles of Gen 2 Ingestion
Offline First: Survey forms cache over 9,000 Kebeles and Primary Cooperatives locally on mobile devices.
Zero-Loss Decoupling: The OpenG2P Connector Service maintains strict cursor timestamps and idempotency keys to ensure exactly-once ingestion.
Four-Eyes Verification: Raw submissions first enter an Intake Staging area (AWE approval workflow) before staff review commits them to permanent registry tables.

2. End-to-End System Architecture

The data flow spans six distinct processing stages from field collection to permanent storage:

1
Mobile Field Collection (ODK Collect on Android)
Enumerators complete surveys offline in English, Amharic, or Afaan Oromo with cascading geography from KebeleList.csv (9,000+ Kebeles) and hardware GPS capture.
↓
2
ODK Central Server (https://odk.13.207.43.8.nip.io)
Project 13 (“Farmer Registry”), Form farmer_profile (v1.0.2). Submissions are stored and exposed via OData REST API (.../farmer_profile.svc/Submissions) with repeat group navigation links.
↓
3
OpenG2P Connector Service (:8050 & Worker)
Pipeline farmer-odk-pipeline-01 polls OData every 30s with resolve_nav_links: true. Maintains checkpoint timestamps, wraps data in OpenG2P envelope, and POSTs to Partner API.
↓
4
Partner Ingest & Celery Worker Transformation
Partner API (:8006/:8000) enqueues task to Redis. Celery worker classifies model FARMER_ODK_MODEL, loads MinIO Jinja2 template (farmer_transform.j2), strips spaces from Fayda UID/RID, formats phones, and unnests repeat arrays.
↓
5
Intake Staging & Approval Workflow Engine (AWE)
Records stage in g2p_intake_form_submissions with status PENDING. Automatic deduplication against registers triggers. Staff reviews submission in Portal UI (:3001).
↓
6
Permanent Farmer Registry Tables
Approved records are atomically committed: g2p_register_farmers, g2p_register_farmer_phones, g2p_register_lands, g2p_register_crops, g2p_register_livestocks.

3.4 Data Routing & Architecture FAQs: Localhost vs. Remote Server

FAQ 1: Why did my colleague's submission from another state appear in my localhost:3001?

The Mechanism: ODK Central (https://odk.13.207.43.8.nip.io) is a single, centralized cloud server hosted on AWS.

The Flow: When a colleague in another state fills out the form in ODK Collect and submits it, the data reaches the shared cloud ODK Central server. If your local Docker stack is running on your laptop, its background container farmer-registry-connector-worker polls the cloud server every 30 seconds, fetches all new submissions across the internet, and stores them in your local PostgreSQL database (localhost:5445). Thus, both your test and your colleague's test appear in your local Staff Portal (localhost:3001).

Conclusion: This proves the end-to-end ingestion pipeline, Jinja2 transformation, and intake staging workflow are 100% operational.

FAQ 2: What happens if the Connector on the server uses localhost instead of the cluster URL?

In Simple Terms: In containerized environments (Docker and Kubernetes), localhost means "inside this pod/container only".

If the connector worker pod on the server sends data to http://localhost:8000, it is looking for the Partner API inside itself, where nothing is listening, resulting in Connection Refused. On the remote server, it MUST use the Kubernetes service DNS: http://farmer-registry-partner-api.far.svc.cluster.local/partner/ingest_data.

OpenG2P Gen 2 Farmer Registry · Technical Reference Section 4 · ODK Form Architecture (v2)

4. ODK Form Design & XLSForm Specifications

The profiling form (odk/ATI_Farmers_Profile_ODK_Form_v2.xlsx) is structured into 14 logical sections, translated into three languages, and integrated with offline lookup datasets.

4.1 Tri-Lingual Language Architecture

  1. English (en): Default base language used for system labels, enumerator instructions, and fallback text.
  2. Amharic (am) — አማርኛ: Official federal working language; native Ethiopic Ge'ez script stored directly in PostgreSQL UTF-8 columns.
  3. Afaan Oromo (om) — Afaan Oromoo: Widely spoken regional language; stored in designated language-specific profile columns.

4.2 Preloaded Media Attachments

  • KebeleList.csv: Over 9,000 Ethiopian Kebeles pre-indexed with hierarchical codes (region_code, zone_code, woreda_code). Uses ODK’s select_one_from_file with dynamic choice_filter for instant cascading drop-downs without memory lag.
  • PrimaryCoopList.csv: Preloaded directory of Primary Agricultural Cooperatives and Unions.

4.3 Complete Questionnaire Section Breakdown

Section Identifier Key Question Fields Technical Characteristics
1. consent_form_section consent_form (agree / disagree) Mandatory gatekeeper. Rejecting exits survey immediately.
2. household_questions household_head, head_registered, relationship_to_head Identifies if respondent is the family head or dependent.
3. national_id_section national_id, national_uid, national_rid, other_id Captures Fayda National ID (16 digits) and RID (29 digits).
4. locale_info region, zone, woreda, kebele, language Cascading administrative boundaries linked to KebeleList.csv.
5. personal_info 3-part names (EN, AM, OM), gender, dob_gc, dob_ec, primary_phone_number, secondary_phone_number, farming_type, disability Supports Gregorian and Ethiopian calendar dates. Normalizes phone numbers automatically.
6. socio_economic_data marital_status, education_level, income_source Captures social vulnerability and livelihood classification.
7. membership primary_cooperative, coop_union, farmer_cluster, primary_commodity Links smallholder to organized agricultural supply chains.
8. land_info_repeat land_ownership, total_land_area, land_id, land_certificate (photo attachment) Repeat group allowing multiple land parcels per farmer.
9. crop_information crop_name_rep, crop_date, crop_water_source Repeat group capturing planted crops and sowing seasons.
10. livestock_info animal_rep, num_animals, livestock_water_source Repeat group capturing cattle, sheep, goats, poultry.
11. agricultural_input Fertilizer, pesticide, insecticide, improved seed use Boolean flags and quantities utilized per season.
12. access_to_resource Machinery access (Tractor, Harvester), Bank loans, Savings Captures mechanization and financial inclusion metrics.
13. other_hh_members Name, relationship, gender, DOB for each member Repeat group registering secondary family members.
14. farmer_location location (geopoint string: lat lon alt acc) High-precision hardware GPS coordinates of the farmstead.

9. Troubleshooting & Operational Runbook

Issue / Error Symptom Root Cause Corrective Action
HTTP 400: An expected header field (X-OpenRosa-Version) did not match ODK Central OpenRosa submission endpoint strictly enforces protocol versioning. Pass -H "X-OpenRosa-Version: 1.0" in the HTTP POST request.
Server error 500: Server error for url 'http://farmer-registry-partner-api:8000/partner/ingest_data' farmer-partner is missing in master_data.g2p_partners or Partner API is unreachable. Run the partner seed SQL in master_data. Inspect container logs: docker logs farmer-registry-partner-api.
FARMER_ODK_MODEL transformation failed in Celery MinIO bucket is missing farmer_transform.j2 or S3 credentials failed. Execute mc cp odk/templates/farmer_transform.j2 myminio/templates/farmer_transform.j2. Check MinIO health at :9002.
Repeat groups (Land / Crops) are missing in Intake Form resolve_nav_links is set to false in the connector source config. Set "resolve_nav_links": true in source_config_json inside connector.connector_definitions.
Connector stops polling or skips recent submissions Cursor boundary is stuck or corrupted in poll_state_json. Reset cursor via API: curl -X POST http://localhost:8050/connectors/farmer-odk-pipeline-01/reset-cursor or clear idempotency keys.
All connection attempts failed in Connector Worker Internal Docker network cannot resolve external DNS for odk.13.207.43.8.nip.io. Test network egress: docker exec -it farmer-registry-connector-worker curl -k -I https://odk.13.207.43.8.nip.io.
Fayda UID validation regex failure Enumerator entered Fayda UID with spaces (e.g. 1234 5678 9012 3456). Sanitized by farmer_transform.j2 via replace(' ', ''). Ensure latest template is active in MinIO.
